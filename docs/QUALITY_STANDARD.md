# GYEOL 지속 개선 기준

개정: 2026-09-14. 이전 UX 상호 리뷰의 P1·P2를 작업 기준으로 전환했습니다. 평가 대상은 실제 관찰·조작 결과입니다.

## 화면 원칙

- 첫 화면의 주인공은 인체 모델입니다. 390×844, 1440×900에서 캔버스가 헤더 바로 아래 시작하고 화면 높이 안에 들어와야 합니다.
- 모바일 도구 패널은 장면 위에서 열리고 높이는 장면의 45% 이하로 유지합니다. 모델을 따로 보러 탭을 왕복하게 하지 않습니다. 비교·확대 실행 후 패널을 닫아 결과를 확인할 수 있게 합니다.
- 도구는 호버·키보드 초점에서 이름을 설명하고 클릭·터치로 실행합니다. Escape로 패널을 닫고 실행 버튼으로 초점을 돌립니다. 키보드로 구조 목록과 카메라 버튼을 사용할 수 있어야 합니다.
- 상세 필터는 필요할 때 펼칩니다. 화면이 작아도 경혈명·코드·분류·현재 상태를 읽을 수 있어야 합니다.
- 색만으로 의미를 전달하지 않습니다. 선택 구조, 전통적 장부 비교, 경혈 참조는 범례·이름·조작 문맥으로 구분합니다.

## 추가 기준: 수록 범위·이동·선명도

- Q11: 누락 판단은 문서의 참조 ID와 원본의 part-of/composite 목록으로 합니다. 근육·장기·신경을 이름 키워드만으로 골라 누락시키지 않습니다. 메쉬 수를 실제 근육 개수로 표현하지 않습니다.
- Q12: 새 버전 모델은 공식 버전 목록·실제 파일 헤더의 이름·원본 해시·공통 좌표를 대조합니다. 신경조직과 뇌실/중심관 공간을 구분하고 원본의 좌우·부위 범위를 표시합니다.
- Q13: WASD/방향키/QE 이동, 키 해제·초점 이탈, 검색 입력, 일반 휠 양방향 확대/축소와 초기화를 실제 브라우저에서 검사합니다. `Alt/Option+휠`은 카메라 거리를 바꾸지 않고 박리 깊이만 변경하며, `Alt/Option+↑/↓` 키보드 경로도 검사합니다. 터치용 6방향 버튼도 제공합니다.
- Q14: 도구의 글자는 최소12px, 밝은 패널의 본문·보조 글자는 대비4.5:1 이상을 목표로 합니다. 흰 패널·명확한 경계·초점 표시를 사용하고 모바일 캡처에서 겹침을 확인합니다.
- Q15: 모델이 늘어나도 장부 비교는 선택 묶음 주위로 화면을 맞춥니다. 위키는 3D·GLB 요청 없이 열립니다(Q9). 아틀라스는 0%에서 모든 계통이 존재해야 하므로(Q20) 체표를 먼저 그리고 내부 계통을 배경에서 함께 불러옵니다. 첫 접속의 모델 전송량(남성 약 64MB, 여성 전환 약 54MB)과 로드 시간을 기록합니다. (2026-09-29 개정: 이전의 ‘초기 체표만 지연 로딩’ 기준을 대체)
- Q20: 깊이 탐색은 0~100 연속 상태(0.5% 단위)를 사용합니다. 0%에서 7계통이 모두 존재하고, 바깥 계통부터 한 겹씩 사라집니다: 피부 → 근육(출처 기반 개별 순서) → 골격 → 장기 → 혈관 → 림프, 신경은 남습니다. 어떤 계통도 박리 도중에 새로 나타나지 않으며, 안쪽 계통은 바깥 계통이 모두 사라진 뒤에만 줄어듭니다(`tests/dissection.test.mjs`). 20%에서 골격·장기가 실제로 렌더링되는지와 근육 메쉬 감소를 브라우저에서 검사합니다. 교육용 표시 순서이지 실제 조직 깊이가 아닙니다. (2026-09-29 개정: 깊어질수록 계통을 추가하던 순서를 대체)
- Q23: 아틀라스 화면은 어두운 관찰 배경과 의학 도해 관례의 피부·근육·골격·동맥·정맥·신경 구분색을 사용하며, 텍스트와 조작부 대비를 모바일·데스크톱에서 확인합니다.
- Q21: 혈관·신경의 전신 보완 모델은 좌우 머리부터 손·발까지의 범위와 출처·해시를 검사합니다. 전신 1,165개 노드는 안정된 ID, 원문명, TA2 라틴명, 계층 경로, 설명을 갖고 검색·클릭·확대·단독 보기·세션 복원이 동작해야 합니다. 미세 말단 전체로 과장하지 않습니다.
- Q22: 골격은 양쪽 손·발가락 마디뼈 56개를 포함하고 한국어·영어·FMA 검색과 단독 확대가 동작해야 합니다.
- Q25: 장면 위 도구(검색·상단 조작·깊이 막대·경혈 막대·경혈 칩과 상세·선택 카드·이동/시점/카메라 도구·상태·범례·출처 줄)는 서로 겹치지 않고, 활성 경혈 이름표는 캔버스 안에 표시합니다. 표식 자체가 캔버스 밖이면 이름표를 가장자리에 고정하지 않습니다. 비교의 전통 대응 한계 문구는 그 비교 카드 안에 둡니다. `npm run test:visual`이 4화면×초기·비교·단독 확대에서 이를 단언하고, `npm run audit:overlays`가 노트북·태블릿 폭을 포함한 8화면을 측정합니다. 호버·초점 말풍선은 일시적 설명이라 제외합니다.
- Q26: 경혈 지도는 여러 경혈을 몸과 함께 봅니다. 남성 기준으로 409개 명칭·834개 표식을 기본으로 몸 위에 표시하고, 경맥 칩·목록 필터로 좁히며, 이름은 표식 호버·선택·‘표식 이름 표시’로 보입니다. 카메라를 향한 면의 표식만 보이고(뒤쪽은 몸을 돌리면 보임) 선택 경혈은 항상 보입니다. 박리 깊이와 무관하게 표식은 체표 기준 위치에 남습니다. 여성 표면 좌표는 검수 전이라 표식을 숨기고 그 이유를 경혈 막대에 표시하되, 장부 비교용 경혈 선택은 유지합니다.
- Q27: 인대·힘줄은 원본에 따로 모델링된 구조만 표시합니다. 근육 메쉬를 힘줄로 바꾸어 부르거나 없는 힘줄을 만들지 않고, 기존 원본과 같은 구조는 중복 메쉬 없이 종류만 구분합니다. 인대·관절 구조는 골격과 함께, 힘줄·힘줄집은 근육과 함께 박리되며, 표시 여부는 보기 상태의 선호로 카메라·표식 선호와 함께 보존됩니다. 영문명·TA2 라틴명·원본 계층을 유지하고 한국어명은 편집 표기로 명시합니다. 전신 보정만 적용한 배치의 뼈 근접도를 측정해 기록합니다.
- Q28: 경혈 표식을 누르는 범위는 그려진 점(거리에 따라 3.6–6.5px)보다 넓은 화면 원입니다(마우스 14px, 호버 중인 표식 22px, 터치·펜 22px; 피부를 걷어내 표식이 근육·장기 위에 떠 있으면 9·14·14px). 그 안의 누름은 앞이나 뒤에 있는 조직보다 경혈을 먼저 선택하고, 범위가 겹치면 화면에서 가장 가까운 표식이 선택됩니다. 호버한 표식은 누를 수 있는 범위를 고리로 보여 주고, 이름표는 고리 밖에 두며 포인터를 가로막지 않습니다. 카메라를 끌어 돌린 누름은 출발점 근처에서 놓아도 선택이 아닙니다. 모델 위에서 직접 누른 구조는 그 자리에서 선택되어 계통·깊이·부위·카메라가 유지되고, 확대는 선택 카드의 ‘확대’로만 합니다. 선택 카드 자리를 비우는 화면 이동은 카메라 거리·방향을 바꾸지 않는 0.32초 미끄럼이며 ‘동작 줄이기’ 설정에서는 즉시 바뀝니다. 목록·검색으로 고른 구조는 이전처럼 그 계통을 열고 맞춥니다(`tests/marker-picking.test.mjs`, `tests/browser/marker-picking.spec.ts`).
- Q29: 남성 Z-Anatomy 보완 구조(신경·혈관·인대·힘줄·림프)의 공통 등록은 두 원본이 공유하는 골격(BodyParts3D 뼈 형상)에 맞춘 균일 축척·이동이며, 머리의 몇 점에만 맞추지 않습니다. 이름이 같은 손뼈 쌍의 남은 강체 이동(0.5mm 미만)과 0% 손·발에서 피부 앞에 보이는 보완 구조의 실제 광선 수(이전 대비 90% 이상 감소)를 단위 검사로 고정합니다(`tests/male-skeleton-registration.test.mjs`). 피부 단순화는 손·발·코·입에 0.4mm, 머리·목 앞에 0.6mm 세부를 남기되 기본 모형 예산을 지키고, 피부가 그려지는 동안 겉면 기관(귀·입술·눈알)과 원본에서 피부와 맞닿는 얼굴 구조는 피부·흰자 톤으로, 겹치는 Z-Anatomy 눈알 구성은 숨기며([얼굴 기록](anatomy-alignment/FACE_SURFACE.md)), 피부를 다시 만들 때 기존 경혈 표식은 같은 면의 가장 가까운 점으로만 옮깁니다. 구조를 피부 안으로 넣기 위해 따로 옮기지 않습니다.
- Q30: 카메라는 사용자가 요청한 카메라 조작(확대·시점·전체 보기·구조 맞춤)과 좌표계가 바뀌는 전환(기관 상세 열기/닫기, 성별·부위 전환)에서만 움직입니다. 기관을 고른 채 경혈을 고르거나 박리·계통을 바꾸거나 선택을 해제해도 카메라는 그대로이고, 선택은 그 메쉬가 계속 그려지는 동안 유지됩니다(숨겨진 단독 선택은 남기지 않음, Q1). 모델에서 직접 누른 구조는 같은 거리에서 회전 중심이 됩니다. 카메라 이동은 미끄러지며 ‘동작 줄이기’ 설정에서는 즉시 바뀝니다([기록](ui-renewal/VIEW_CONTINUITY.md)).
- Q24: 남성·여성 참조 전환은 여성 고유 원본과 성별 공통 보완 구조를 구분합니다. 여성 보기에서도 7개 계통 전체를 제공하되 공통 보완을 여성 전용 원본으로 주장하지 않습니다. 여성에 없는 계통은 남성 원본을 여성 고유 뼈·피부에 맞춘 하나의 정합장으로 옮기고(`FT_` ID, 출처 ‘여성 정합 보완’), 여성 원본이 이미 가진 구조와 남성 전용 구조는 옮기지 않습니다(Q31). 전신·머리·상체·하체·팔·손·다리·발·가슴·배·골반 선택은 공통 보기 상태를 거쳐 가시 구조와 카메라 관찰 부위를 함께 바꿉니다. 림프는 별도 계통으로 검색·선택·확대하며 원본별 범위와 출처·라이선스를 표시합니다.

- Q31: 여성 정합 보완은 접힘 없는 하나의 정합장(관절 분절 자세 + B-스플라인 잔차 + 피부층)으로 만들고, 맞춤에 쓰지 않은 피부·여성 고유 뼈 점의 오차(중앙 2mm·2.5mm 미만), 접힘 비율(0.02% 미만), 계통별 여성 피부 밖 정점과 뒤집힌 삼각형을 단위 검사로 고정합니다. 피부를 뚫는 보완 뼈와 다른 부위 변환으로 놓였던 보완 흉곽은 기준이 아니며 같은 정합장으로 다시 놓습니다(빗장뼈–복장뼈 2mm 미만). 0% 여성 노출 광선은 이전 대비 5% 미만이고, 남은 것은 원본에서 피부와 1mm 이하로 맞닿는 구조로 피부색으로 그립니다. 옮긴 근육은 남성 박리 순서를 따르고, 별도 기증자 다리 근육은 검색할 때만 보입니다. 머리뼈를 피부 안으로 옮기며 늘어난 Allen 뇌 교차(55→87쌍) 같은 교환은 숨기지 않고 앱 문구에 적습니다([기록](anatomy-alignment/FEMALE_TRANSPORT.md), `tests/female-transport.test.mjs`, `tests/browser/female-transport.spec.ts`).
- Q32: ‘성기 가리기’는 상단 막대의 별도 버튼(방패, `aria-pressed`)과 표시 설정 체크박스 두 곳에서 같은 `view-state` 선호를 바꿉니다. 남녀 모두 외부생식기 구조를 숨기고 매끄러운 덮개를 피부 위에 그리며, 성별 전환·박리·부위·초기화·새로고침에도 유지됩니다. 검색으로 직접 고른 구조는 보이고, 덮개는 클릭을 가로채지 않습니다(`tests/modesty.test.mjs`, 브라우저 검사).

## 실행할 검증

- `npm test`: 데이터·실제 GLB·참조·앵커·API·보기 상태·저장 복원.
- `npm run test:e2e`: 검색·북마크·경혈 클릭·필터·6계통·묶음·시점·절개·직접 선택·위키 복귀·모바일·실패 경로.
- `npm run build`: 데이터 재생성·타입 검사·정적 빌드.
- `npm run test:production`: 배포 산출물의 지연 로딩·모델·확장 위키·API. 공개 배포 후에는 `SMOKE_ORIGIN`으로 실제 HTTPS를 검사합니다.
- `node scripts/check-readability.mjs`: 모바일 도구 패널에서 실제 계산된 글자 크기·색상 대비를 검사합니다. `SMOKE_ORIGIN`으로 공개 주소를 지정할 수 있습니다.
- `npm run test:visual`: 데스크톱/모바일의 초기·도구·비교·묶음 화면과 측정치를 저장하고 Q25의 도구 비중첩·이름표 위치를 단언합니다. 자동 검사는 실제 이미지를 눈으로 검토하는 절차를 대체하지 않습니다.
- `npm run audit:overlays`: 표준 4화면 밖의 노트북·태블릿 폭까지 장면 도구 겹침과 이름표 위치를 측정해 `docs/anatomy-alignment/scene-overlays.json`에 기록합니다.

문구만 바꾸는 경우 영향 없는 무거운 검사를 반복할 필요는 없습니다. 상태·레이아웃 변경은 해당 시나리오와 화면을 반드시 검증하고, 실패가 있으면 ‘완료’로 기록하지 않습니다.
