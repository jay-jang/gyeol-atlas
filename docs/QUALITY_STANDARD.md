# GYEOL 지속 개선 기준

개정: 2026-09-14. 이전 UX 상호 리뷰의 P1·P2를 작업 기준으로 전환했습니다. 평가 대상은 실제 관찰·조작 결과입니다.

## 화면 원칙

- 첫 화면의 주인공은 인체 모델입니다. 390×844, 1440×900에서 캔버스가 헤더 바로 아래 시작하고 화면 높이 안에 들어와야 합니다.
- 모바일 도구 패널은 장면 위에서 열리고 높이는 장면의 45% 이하로 유지합니다. 모델을 따로 보러 탭을 왕복하게 하지 않습니다. 비교·확대 실행 후 패널을 닫아 결과를 확인할 수 있게 합니다.
- 도구는 호버·키보드 초점에서 이름을 설명하고 클릭·터치로 실행합니다. Escape로 패널을 닫고 실행 버튼으로 초점을 돌립니다. 키보드로 구조 목록과 카메라 버튼을 사용할 수 있어야 합니다.
- 상세 필터는 필요할 때 펼칩니다. 화면이 작아도 경혈명·코드·분류·현재 상태를 읽을 수 있어야 합니다.
- 색만으로 의미를 전달하지 않습니다. 선택 구조, 전통적 장부 비교, 경혈 참조는 범례·이름·조작 문맥으로 구분합니다.

## 추가 기준: 수록 범위·이동·선명도

- Q11: 누락 판단은 문서의 참조 ID와 원본의 part-of/composite 목록으로 합니다. 근육·장기·신경을 이름 키워드만으로 골라 누락시키지 않습니다. 메쉬 수를 실제 근육 개수로 표현하지 않습니다.
- Q12: 새 버전 모델은 공식 버전 목록·실제 파일 헤더의 이름·원본 해시·공통 좌표를 대조합니다. 신경조직과 뇌실/중심관 공간을 구분하고 원본의 좌우·부위 범위를 표시합니다.
- Q13: WASD/방향키/QE 이동, 키 해제·초점 이탈, 검색 입력, 휠 양방향 확대/축소와 초기화를 실제 브라우저에서 검사합니다. 터치용 6방향 버튼도 제공합니다.
- Q14: 도구의 글자는 최소12px, 밝은 패널의 본문·보조 글자는 대비4.5:1 이상을 목표로 합니다. 흰 패널·명확한 경계·초점 표시를 사용하고 모바일 캡처에서 겹침을 확인합니다.
- Q15: 모델이 늘어나도 장부 비교는 선택 묶음 주위로 화면을 맞춥니다. 초기 체표와 위키의 지연 로딩을 유지하며 용량 증가를 기록합니다.
- Q20: 체표→근육→골격→장기→혈관→신경의 깊이 탐색은 슬라이더·휠·계통 버튼이 같은 보기 상태를 사용하고 현재 단계를 명시합니다.
- Q21: 혈관·신경의 전신 보완 모델은 좌우 머리부터 손·발까지의 범위와 출처·해시를 검사합니다. 보완 오버레이와 개별 검색 가능한 구조 수를 구분하고 미세 말단 전체로 과장하지 않습니다.
- Q22: 골격은 양쪽 손·발가락 마디뼈 56개를 포함하고 한국어·영어·FMA 검색과 단독 확대가 동작해야 합니다.

## 실행할 검증

- `npm test`: 데이터·실제 GLB·참조·앵커·API·보기 상태·저장 복원.
- `npm run test:e2e`: 검색·북마크·경혈 클릭·필터·6계통·묶음·시점·절개·직접 선택·위키 복귀·모바일·실패 경로.
- `npm run build`: 데이터 재생성·타입 검사·정적 빌드.
- `npm run test:production`: 배포 산출물의 지연 로딩·모델·확장 위키·API. 공개 배포 후에는 `SMOKE_ORIGIN`으로 실제 HTTPS를 검사합니다.
- `node scripts/check-readability.mjs`: 모바일 도구 패널에서 실제 계산된 글자 크기·색상 대비를 검사합니다. `SMOKE_ORIGIN`으로 공개 주소를 지정할 수 있습니다.
- `npm run test:visual`: 데스크톱/모바일의 초기·도구·비교·묶음 화면과 측정치를 저장합니다. 자동 검사는 실제 이미지를 눈으로 검토하는 절차를 대체하지 않습니다.

문구만 바꾸는 경우 영향 없는 무거운 검사를 반복할 필요는 없습니다. 상태·레이아웃 변경은 해당 시나리오와 화면을 반드시 검증하고, 실패가 있으면 ‘완료’로 기록하지 않습니다.

## 비교와 다음 반복

상용 서비스는 공개 데모·지원 문서·이미지에서 관찰 가능한 패턴만 비교합니다. 계정이 필요한 기능이나 사용해 보지 않은 성능을 검증했다고 쓰지 않습니다. 출처·이미지 날짜·채택/보류 이유는 `docs/ui-renewal/COMMERCIAL_COMPARISON.md`에 기록합니다.

다음 개선의 사용자 과업은 중완→위 비교→단독 확대→가이드→복귀, 태계→양쪽 콩팥, 족삼리 확대→계통 교대입니다. 실제 사용자 테스트를 진행할 때 완료 여부·재검색·되돌아가기 횟수와 강조 의미의 해석을 기록합니다. 이번 자동·전문가 검토를 사용자 성공률이나 임상 검증으로 바꾸어 주장하지 않습니다.
