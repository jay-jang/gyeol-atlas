# Codex 사양 교차 검증 (2026-10-25, gpt-6.1-sol)

**결론: 조건부 승인.** 통합 방향은 요청에 맞지만, 아래 차단 2건과 주요 4건을 사양에 반영해야 합니다. 별도 ‘계통 빼기’ 모드·완료 버튼을 없애고 같은 행에서 조작하는 결정은 적절합니다.

검토 기준은 [SPEC.md](SPEC.md)와 현재 코드·품질 기준·검증 기록·기존 PNG입니다. 파일은 수정하지 않았으며 다른 검토자의 결과도 읽지 않았습니다.

1. **[차단] 체크 표시 CSS가 계통색을 지웁니다.**
   - 위치: 사양 §4, 173·183행.
   - 근거: 계통색을 `background-color`로 지정한 뒤 `:checked{background:no-repeat … url(…)}`를 적용하면, shorthand가 색을 `transparent`로 초기화합니다. 두 선택자의 명시도도 같습니다. 체크 잉크 `#062028`의 실제 바탕 대비는 약 **1.02:1**로, §1의 3.60:1이 성립하지 않습니다.
   - 수정: `background-image`, `background-position`, `background-size`, `background-repeat`만 지정하세요. 검사에도 포함된 7계통의 **계산된 배경색과 체크 대비**를 추가해야 합니다.

2. **[차단] 가로 휴대폰 그리드에 필요한 CSS 재정의가 빠졌습니다.**
   - 위치: 사양 §2 ‘Short landscape’, 현재 `src/atlas.css:315`, `:321`, `:848`.
   - 근거: 기존 `li`는 `position:absolute; top:var(--stop-top); transform:translateY(-50%)`입니다. 부모를 grid로 바꿔도 행은 정상 grid 배치에 참여하지 않습니다. 체크는 기본 24×26, 눈은 26×26이며, 태블릿 44px 규칙은 `min-height:561px`여서 가로 휴대폰에 적용되지 않습니다.
   - 수정: 가로 화면에도 `li`의 `position:static; transform:none; display:flex`와 체크·이름·눈 각각의 44px 크기를 명시하세요. 비교 고지와 cell 8의 배치 규칙도 함께 완성해야 합니다.

3. **[주요] 세 조작의 구별이 첫 조작 뒤 사라집니다.**
   - 위치: 사양 §1, §2 55·60–65행, §3 110행.
   - 근거: 휴대폰 범례는 `keepNote`로 대체되고, 1024×680 터치 레일은 설명 자체를 숨깁니다. 눈의 접근 이름도 ‘빠른 보기’여서 ‘이것만 보기’를 설명하지 못합니다. 체크와 눈을 모두 표시 토글로 오해할 여지가 남습니다.
   - 수정: **‘포함 / 여기까지 박리 / 이것만 보기’ 역할 표시는 유지**하고 결과 알림만 교체하세요. 낮은 터치 레일에는 짧은 열 제목을 쓰고, 눈의 접근 이름은 ‘○○만 보기’로 명확히 하세요.

4. **[주요] 마지막 계통 안내와 부위 변경 후 안내가 잘못될 수 있습니다.**
   - 위치: 사양 §3 98·107·110행.
   - 근거: `keepNote || … lastKept …` 순서 때문에 여섯 번째 제외 직후에도 LAST 대신 직전 결과가 표시됩니다. 또한 부위 변경은 `keepNote`를 비우지 않습니다. 예를 들어 장기가 가장 안쪽인 전신에서 ‘76%까지’를 표시한 뒤 팔·손으로 바꾸면 실제 한계는 68%지만 이전 안내가 남습니다.
   - 수정: 마지막 계통의 불가 사유를 우선 표시하세요. 부위·제외 집합·깊이 변경 시 과거 결과 문구를 해제하거나 현재 상태에서 다시 계산하되, 부위 변경을 불필요하게 재공지하지 않도록 하세요.

5. **[주요] 단계·눈 실행으로 띠를 닫을 때 초점 복귀가 없습니다.**
   - 위치: 사양 §1 ‘Eye’, §3 ‘Focus’, 현재 `src/AtlasPage.tsx:948`, `:951`.
   - 근거: 두 버튼은 `setPopover(null)`로 자기 자신을 숨깁니다. Escape 경로만 초점을 돌려주므로 키보드 실행 후 초점이 숨겨진 버튼에 남거나 문서로 이탈할 수 있습니다.
   - 수정: 휴대폰·가로 화면에서는 실행 후 단계 펼침 버튼으로 초점을 돌리세요. Enter·Space 실행과 다음 Tab 위치를 검사에 추가하세요. cell 8에서 슬라이더로 보내는 계획은 적절합니다.

6. **[주요] 가독성 검사 계획이 띠 내용을 실제로 측정하지 못합니다.**
   - 위치: 사양 §5 268행·§7, `scripts/check-readability.mjs:11–14`, `:56`.
   - 근거: 현재 `measure(root)`는 텍스트가 root의 세로 범위와 겹치는지 검사합니다. 휴대폰의 띠와 단계는 44px 깊이 줄 **위에** 있으므로, 열린 `.ax-depth`를 다시 측정해도 대부분 제외됩니다. SVG 존재 검사만으로는 1번 결함도 발견하지 못합니다.
   - 수정: 열린 `.depth-band`와 `.depth-steps`를 각각 측정하세요. 가로 화면 aside, 마지막 계통 안내, 체크 색·대비, 실행 후 초점, 부위 변경 안내도 검증 항목에 넣으세요.
