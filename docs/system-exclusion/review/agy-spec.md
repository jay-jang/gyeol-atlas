# AGY 사양 교차 검증 (2026-10-25, Gemini 3.8 Flash high)

### 검토 결론: 조건부 승인

사양(`SPEC.md`)은 사용자의 “계통빼기 보다는 박리 화면에 아예 integration 하는 ui로 변경해줘”라는 요구를 정확히 만족합니다. 기존의 독립된 '계통 빼기' 버튼·팝오버 선택기·'완료' 조작을 제거하고, 박리 단계 각 행에 '포함 체크박스'를 직접 통합했습니다. 레이아웃 안전(45% 상한, 44px 터치, 12px·대비 기준)과 상태 불변(view-state 단일 경로, 7개 전체 제외 방지, 팔·손 장기 멈춤)도 충실히 계승했습니다. 단, 아래 지적된 주요 결함 및 기하 오차를 수정한 후 구현에 착수하는 조건으로 승인합니다.

---

### 지적 사항

1. **[주요] `toggleKept` 스코프 참조 오류**
   - **위치**: 사양 3절 (SPEC.md:102-108)
   - **근거**: `toggleKept(layer, keep)` 내에서 `setKeepNote(`${name} ...`)`를 호출하지만, `AtlasPage` 함수 스코프에는 `name` 변수가 없고 939줄 렌더링 루프 내부에만 존재하므로 런타임에 `ReferenceError`가 발생합니다.
   - **고칠 방법**: `layerNames[layer]`를 참조하거나 `toggleKept(layer, keep, name)`으로 `name`을 전달하도록 수정하세요.

2. **[주요] 높이 700px 이하 터치 태블릿에서 시각적 상태 피드백 부재**
   - **위치**: 사양 2절 (SPEC.md:55), 3절 (SPEC.md:146)
   - **근거**: 1024×680 터치 화면에서는 44px 간격 확보를 위해 `:is(.depth-excluded,.depth-keep-hint){display:none}` 처리됩니다. 태블릿 터치 환경은 호버 툴팁이 없고 `.depth-status`는 스크린리더 전용(`.ax-vh`)이므로, 마지막 1개 해제 시도 거부나 뺀 단계 탭 시 시각적 안내가 전혀 보이지 않습니다.
   - **고칠 방법**: 터치 탭 시 상태 줄(`.ax-status`)이나 공통 알림(`.ax-link-notice`)을 통해 시각적 피드백을 전달하도록 보완하세요.

3. **[주요] 가로 휴대폰 최소 폭 구간(701–760px) 자동 검증 누락**
   - **위치**: 사양 5절 (SPEC.md:240-250)
   - **근거**: 사양 6절 한계에 명시되었듯 가로 701–715px에서는 단계 이름 폭이 40–44px로 축소됩니다. 그러나 5절 테스트 계획에는 844×390과 740×360만 포함되어 있어 701–715px 구간의 텍스트 줄바꿈 및 여백 축소가 회귀 테스트에서 누락됩니다.
   - **고칠 방법**: `system-exclusion.spec.ts`의 `h` 또는 `scripts/audit-scene-overlays.mjs`에 `710×360` 뷰포트 기하 검증을 추가하세요.

4. **[경미] 가로 휴대폰 띠의 `left` 및 `--lw` 계산 오차**
   - **위치**: 사양 2절 (SPEC.md:81-82)
   - **근거**: `.ax-depth`는 `left: 10px`, `border: 1px`, `padding: 8px`이므로 padding box 우측은 `x = 133px`입니다. `left: calc(100% + 17px)`를 주면 실제 띠 시작 위치는 `x = 150px`가 되어 사양에 적힌 `x = 142px`와 8px 차이가 납니다. 이로 인해 701px 폭에서 우측 여백이 `--ax-gap`(10px)이 아닌 `2px`로 줄어듭니다.
   - **고칠 방법**: `x = 142px`가 목표라면 `left: calc(100% + 9px)`로 조정하고, `x = 150px`를 유지할 경우 `--lw: min(580px, calc(100vw - 160px))`로 수정하여 최소 10px 여백을 확보하세요.

5. **[경미] 사양서 오타**
   - **위치**: 사양 5절 c) 항목 (SPEC.md:215)
   - **근거**: `"장기 포231함"`으로 오타가 기재되어 있습니다.
   - **고칠 방법**: `"장기 포함"`으로 수정하세요.

### 검토 항목별 평가 요약

1. **요청 충족**: 별도 모드·선택창이 완전히 사라지고, 연속 박리 상태에서 각 계통별 체크박스로 직관적 통합이 이루어졌습니다.
2. **사용성**:
   - 체크박스(박리 포함 여부)와 눈 아이콘(단독 보기)의 기능 차이는 데스크톱 캡션, 모바일 범례 힌트, 비박리 모드 시 체크박스를 정적 견본(`is-static`)으로 치환하는 처리를 통해 혼동을 성공적으로 차단했습니다.
   - 가로 휴대폰에서 단계를 팝오버 띠(100px, 장면의 28.9~31.6%)로 분리한 것은 기존 20px 겹침(-6px) 버그를 해결하고 44px 터치를 보장한 명백한 개선입니다(단계 점프가 1탭 늘어난 것은 합리적 트레이드오프).
3. **레이아웃 안전**:
   - 데스크톱/태블릿: 1180×580 트랙 222.3px(필요 190.5px), 1024×680 트랙 313.5px(필요 293.5px)로 겹침 없음.
   - 세로 휴대폰: 390(33%), 360(38%), 360 비교 모드(40.7%) 모두 장면 45% 이하 규칙 준수.
   - 가로 휴대폰: 844(28.9%), 740(31.6%), 740 비교 모드(44.7% ≤ 45%) 모두 통과.
   - 글자 크기 모두 ≥12px, 견본 대비 ≥3.67:1, 잉크 대비 ≥3.60:1, 빈 사각 대비 8.74:1 확인.
4. **접근성**: 21개 탭 스톱 유지, `aria-disabled` 처리, 영구 DOM `<span hidden>`을 통한 `aria-describedby` 참조 무결성, Escape 계층 닫기 모두 적절합니다.
5. **규칙 위반 여부**: `view-state.ts` 우회 없음, 7개 모두 빼기 방지 및 팔·손 장기 멈춤 불변식 보존, 표시 설정 체크박스 독립성 유지 확인.

---

### 더 단순하거나 나은 대안

- **접근 이름 구체화**: 체크박스 `aria-label`을 `"${name} 포함"` 대신 `"[박리] ${name} 포함"`으로 지정하면, 표시 설정 패널의 `"${name} 레이어"` 체크박스와의 역할 차이(연속 박리 참여 vs 직접 켜기)가 스크린리더 사용자에게 더 직관적으로 구분됩니다.

### 확인 필요 (환경적 한계로 직접 검증하지 못한 항목)

- 실제 iOS Safari 실기기에서 체크박스 탭 시 포커스 이동 여부 및 힌트 텍스트 반응성.
