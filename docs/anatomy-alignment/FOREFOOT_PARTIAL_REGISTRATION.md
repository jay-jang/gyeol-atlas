## 후보 생성과 탈락 조건

첫째~넷째 발가락은 발허리뼈를 고정하고 근위마디뼈와의 양방향 정점-표면 근접 패치 평균을 회전 중심 대용값으로 삼았습니다. 끝점을 향하는 수평 방향과 수직축으로 회전축을 구성했습니다. 중심·축은 해부학적으로 표지된 실제 관절축이 아닙니다. 각±20°의 기술적 범위에서4° 간격 탐색 후 주변0.5° 간격 탐색을 수행했습니다. 이 각도는 앱의0.5% 박리 입력과 별개입니다.

목표 함수는 피부 밖 거리에서2mm를 뺀 값의 제곱합과 작은 회전량 벌점입니다. 새 이탈·기존 이탈 거리 악화·불명확한 판정이 있으면 제외합니다. 회전만 적용한 발 전체 이탈은1,238개이고 접합부 교차가 남았습니다. 이후0.25mm 간격·이동량2mm 이내에서 묶음 전체를 이동해 최종0~1.6202mm 이동을 선택했습니다. 다른 모든 골격과의 표면 교차 및 피부 조건을 확인하고 최종 합성 결과를 다시 전수 쌍 검사했습니다. 순차 탐색이라 순서 의존성이 있고 전역 최적해라고 주장하지 않습니다.

다섯째 줄은 입방뼈를 고정하고 다섯째 발허리뼈+발가락을 회전하는 가설도 시험했지만 피부 조건을 만족하며 개선하는 후보를 찾지 못했습니다. 항등변환으로 남아 **후속 이동 탐색은 건너뛰었습니다**. 회전+이동 모든 조합의 불가능성 증명은 아닙니다. 남은 이탈은 왼쪽 다섯째 줄653·오른쪽521·뒤꿈치56·교정한 발가락 끝3정점입니다.

발 중간 관절별 움직임이 같지 않다는 [사체 연구](https://pubmed.ncbi.nlm.nih.gov/2613125/)는 발 전체 변환을 일반적인 관절 모델로 취급하지 않는 참고 근거입니다. 연구의 운동 범위를 이 기증자의 정상 범위로 대입하거나 위 기술적 탐색 경계의 근거로 쓰지 않았습니다.

## 재현

이전 발 진단과 BodyParts3D 원본 캐시가 있는 작업공간에서 다음 순서로 실행합니다. 원본 manifest·청크 해시를 확인하고 이력이 다른 입력이면 중단합니다.

```sh
npm exec --yes --package=node@24.14.0 -- node scripts/experiment-forefoot-rotation.mjs
npm exec --yes --package=node@24.14.0 -- node scripts/experiment-forefoot-clearance.mjs
npm exec --yes --package=node@24.14.0 -- node scripts/audit-forefoot-candidate.mjs --clearance
npm exec --yes --package=node@24.14.0 -- node scripts/build-forefoot-registration.mjs
```

마지막 명령의 기본 출력은 캐시입니다. `--export`가 있어야 runtime catalog를 쓰며 새 이탈·새 교차·관절 분리·강체성·출처 조건을 통과해야 합니다. 전체 피부 재검사는 역사 파일을 덮어쓰지 않도록 `CONTAINMENT_OUTPUT=docs/anatomy-alignment/body-containment-female-toe-v1-all.json`을 지정해 `scripts/audit-body-containment.mjs --all-female-vertices`를 실행합니다. 캡처는 `scripts/capture-forefoot-registration.mjs`입니다.
