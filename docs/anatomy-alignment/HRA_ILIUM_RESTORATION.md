# 오른쪽 엉덩뼈 원본 표면 복원 — 2026-09-27

**여성 `HRAF0827` 오른쪽 엉덩뼈 치밀뼈 한 조각을 HRA 원본 표면으로 복원했습니다.** 위치를 임의로 옮기거나 맞춘 것이 아니라, 단순화된 표면을 공식 원본 정점·삼각형으로 교체했습니다. 기존 나머지1,219개 모형과 팔/발가락 부분 정합은 그대로입니다.

## 보정 후보와 기준 자료를 구분한 감사

앞선 기증자 골반–대퇴골 맞춤의 교차를 해석하기 전에, 현 앱이 사용하는 HRA 원본 조합과 포장 자료를 대조했습니다. 골반6조각×대퇴골16조각×양측=192쌍을 검사했고 원본 조합에는 교차 증거5쌍, 포장 자료에는6쌍이 있었습니다. 원본 조합은 **v1.10의 엉덩뼈/대퇴골과 복원 수록된 v1.5의 두덩뼈/궁둥뼈8조각**이며, 단일 릴리스의 전체 관절 검사가 아닙니다. [조각별 원본·정점·교차 증거](hra-hip-source-crossings.json).

새 포장 교차는 오른쪽 엉덩뼈 치밀뼈 `HRAF0827`–대퇴골 본체 `HRAF0911` 사이였습니다. 이 두 조각은 **동일 v1.10 원본**에서 직접 대조했습니다. 엉덩뼈만 원본으로 바꾸면 새 교차가 검출되지 않고, 대퇴골만 바꾸면 남았습니다. 따라서 대퇴골이나 전체 골격을 바꾸지 않고 엉덩뼈 한 조각만 복원했습니다. 원본 자체의 교차를 모두 단순화/정합 탓으로 일반화하지 않습니다.

주변 검사에는 현재 팔/발가락의 정적 보정을 적용하고, 기본 숨김인 임신·중복 근육도 포함했습니다. 나머지 조직의 형상을 바꾸지 않았습니다. [검사 기록](hra-ilium-restoration.json). ‘12쌍 남음’은 분명히 유지하며, 교차0이나 골반 전체 정합 완료라고 하지 않습니다. 각 쌍의 첫 삼각형 내부 관통 증거만 수집했으며, 고체 관통 깊이·완전 포함·임상 손상 측정이 아닙니다.

별도의 `@gltf-transform/core` 판독기로 공식 GLB를 다시 읽어 **모든 정점이 원본+기존 피부 공통 이동의 Float32 결과와 일치**하고 모든 인덱스가 원래 순서임을 확인했습니다. 법선은 원본 세계좌표 법선 행렬과 정규화를 적용했고 최대 차이2.980×10⁻⁸입니다. [독립 판독 결과](hra-ilium-restoration-readback.json). 재정합·추가 단순화는 하지 않았습니다.

## 앱 동작과 검증

`PackedAtlas`는 여성 전신 청크와 복원 파일을 함께 기다리고, 화면 준비 전에 한 번만 표면을 교체합니다. 데이터셋·원본 ID·계통·이전 정점/인덱스 수·파일 크기를 확인하며 다른 성별·독립 자료에는 적용하지 않습니다. 그 뒤 기존 팔/발가락 처리, 경계 계산, `view-state` 가시 상태가 이어집니다. 선택이나 박리로 정점을 다시 바꾸지 않습니다.

- 단위110/110: 원본 판독의 합성 좌표/법선 검사, 정확히1개 교체와1,219개 미변경, 성별/CT 차단, 버전/파일 오류, 바이너리/독립 판독/검사 기록 대조 포함.
- 새 브라우저2/2: **201개 모든0.5% 입력**에서 실제 장면의 정점·법선·인덱스 공유 버퍼 SHA 동일. 선택·단독·확대·새로고침·성별 복귀와 위키/남성의 복원 모형 요청0 확인. 별도503 실패/재시도에서 오류를 표시하고 남성 모형으로 대체하지 않은 채 복원된5,907정점을 다시 로드했습니다. 201단계는 소프트웨어 WebGL에서 약3분 걸렸으며 실제 해부학적 박리 층서를 검증한 것은 아닙니다.
- 기존 관련 브라우저11/11: 팔/발가락과 전신1,220개 좌표 해시, 대퇴골 상세, CT 분리·복귀·실패, 최초 화면/다운로드 취소, 자료 전환/로딩 완료 검사.
- TypeScript·프로덕션 빌드·프로덕션 스모크 통과. 큰 JS 청크 경고는 남습니다.

초기 새 브라우저 검사는 파일명이 같은 개발용 JS/메타데이터 요청까지 모형 다운로드로 세어 실패했습니다. `/models/female-source-restoration/`만 검사하도록 고쳤습니다. 전신 좌표 회귀는 이번 복원1개의 옛 포장 해시 때문에 실패했고, 그 조각만 독립 복원 바이너리의 정점 범위와 비교하도록 수정한 뒤 통과했습니다. 다른1,219개의 해시 검사를 제외하거나 허용오차로 바꾸지 않았습니다.

초기 피부 검사 호출은 Three.js `Vector3` 대신 일반 좌표 객체를 넘겨 중단됐습니다. 호출 형식을 고친 뒤 전체 원본 정점/주변 관계 검사를 재실행했습니다. 실제 박리 검사에서는 법선·인덱스가 해시 대상 버퍼를 공유하는지와 각 오프셋·개수도 확인합니다.
