# 장면 하단 안내·시점 도구 배치와 경혈 이름표 위치

2026-09-29. 이전 기록에 남은 두 화면 결함(모바일 비교의 경혈 이름표 왼쪽 잘림, 가로 단독 보기의 하단 범례·조작부 혼잡)을 원인부터 교정했습니다. 해부 모델·좌표·선택 묶음·박리·보기 상태 전이는 바꾸지 않았습니다.

## 수정 전 직접 측정

코드 `1ce9194`에서 `#atlas/CV12` → 위 비교 → ‘비교 대상만 보기’ → 확대를 실제 브라우저로 실행하고, 장면 위 도구의 실제 경계 사각형을 측정했습니다(Chromium·소프트웨어 WebGL).

원인은 두 가지였습니다. 하단의 다섯 요소가 세 CSS 파일에서 서로를 알지 못하는 절대 좌표(`bottom`/`left`/`transform`)와 겹겹의 미디어 규칙으로 배치됐습니다. 이름표는 표식에서 세계 좌표 −0.06m 떨어진 고정 위치여서 확대할수록 화면상 거리가 커졌습니다. 기존 화면 게이트는 캔버스와 카드의 화면 내 위치만 검사해 이 겹침을 발견하지 못했습니다.

## 전체 브라우저 회귀에서 드러난 기존 결함

이번 배치 변경 후 전체 브라우저 검사 103개를 한 번에 실행했습니다(30.1분). 98개 통과, 5개 실패였습니다. 다섯 실패는 모두 이전 커밋 `975155f`에서 시작됐습니다. 그 커밋의 기록은 바뀐 시나리오 33개만 실행했다고 밝히고 있습니다. 수정 전 소스에서도 대표 두 검사가 같은 이유로 실패함을 재현했습니다.

| 실패 | 원인 | 조치 |
| --- | --- | --- |
| 4개 검사(`anatomy`, 남성 `organ-region`·`selection-context`·`selection-peel-return`)의 모호한 선택자 | 새 남성 4.0 상세의 위(`BP4_FJ2564`)와 오른 콩팥(`BP4_FJ3147`)이 FMA ID로 전신 `FMA7148`·`FMA7204`를 함께 인용해 검색 결과가 두 개 | 검사가 전신 메쉬를 명시하도록 `BP4_` 항목을 제외. 앱 동작 변경 아님. 남성 상세 754개 중 이 두 개만 해당 |
| 척수 분절 29개를 차례로 고를 때 두 번째 선택 불가 | `975155f`가 모든 선택에서 카드 내용을 선택마다 새로 만들도록 넓혀, ‘세부 구조 N개 선택’ 목록이 선택할 때마다 닫힘. 실제 사용자도 매번 다시 열어야 했음 | 새 이름이 위에서 보이도록 하는 재생성은 유지하고, 같은 성별·같은 기관 안에서는 목록의 열림 상태를 유지. 다른 기관·성별·선택 해제 뒤에는 닫힌 상태로 시작 |

첫 열림 상태 수정은 기관 ID만 기준으로 삼아 남성 심장에서 연 목록이 여성 심장에서도 열린 채 시작했고, `details.spec.ts`의 표면 선택 검사가 이를 잡았습니다. 성별·기관 범위와 선택 해제 초기화를 더한 최종 코드에서 해당 5개와 세부 목록을 쓰는 관련 검사 전체 44개를 다시 실행해 통과했습니다(10.4분). 처음 103개 실행은 이 열림 상태 수정 전 코드였으며, 이후 변경은 세부 목록을 쓰는 이 44개 범위에만 영향을 줍니다.

## 한계

- Chromium의 모의 뷰포트와 소프트웨어 WebGL 검사입니다. 실제 휴대폰·태블릿, 다른 브라우저, 사용자 과업 성공률을 검증하지 않았습니다.
- 도구 이름 말풍선(호버·키보드 초점 설명)은 일부러 다른 도구 위에 뜨는 일시적 설명이라 비중첩 검사에서 제외했습니다. 게이트는 캡처 전에 포인터를 헤더 모서리로 옮깁니다.
- 701–1200px 폭에서는 키 안내 줄을 숨깁니다. 같은 정보는 이동 도구의 `WASD · Q/E`, 캔버스의 접근 가능한 이름, 박리 슬라이더 안내에 남습니다.
- 이름표가 반대편으로 넘어가면 몸 바깥이 아니라 안쪽을 향할 수 있습니다. 잘려서 읽을 수 없는 경우보다 낫다고 판단했습니다.
- 전체 해부 정합·기관/신경 위치·실제 박리 층서 목표와는 별개의 화면 배치 교정이며, 그 목표는 계속 미완료입니다.
