# 같은 경혈 재선택과 위키 주소 복귀의 구분

2026-09-28. 기존 `view-state.ts`의 경혈 전이는 ID가 현재 경혈과 같고 기관 상세 화면이 아니면 즉시 반환했다. 따라서 50.5% 박리에서 일반 장기를 선택해 장기 단독 레이어가 된 뒤 **현재 경혈을 다시 클릭**하면, 경혈을 명시적으로 선택했는데도 장기 선택과 단독 레이어가 남는 경로가 있었다. 다른 경혈을 선택하거나 ‘구조 선택 해제’를 누르는 경우와 달랐다.

명시적인 `point` 전이는 같은 ID라도 일반 구조 선택·비교·박리 복귀 기록이 있으면 `leaveSelection`을 거쳐 선택을 끝낸다. 원래 0.5% 단위 깊이, 계통 가시성, 카메라, 표식 설정은 기존 복귀 기록을 따른다. 반면 위키에서 `#atlas/현재경혈`로 돌아오는 것은 새 클릭이 아니라 주소 동기화다. 이를 같은 보기 상태 리듀서의 `route-point` 전이로 구별해, 같은 ID에서는 선택을 보존하고 다른 ID일 때만 기존 경혈 전이를 실행한다. 새 독립 레이어·선택 제어 경로는 만들지 않았다.

| 확인 범위 | 결과 | 한계 |
| --- | --- | --- |
| 남녀 일반 장기 선택→같은 경혈 재선택 | 단위 검사에서 50.5% 박리·원래 레이어·카메라·표식 복원 | 실제 GPU 장면과 클릭/터치 결과는 아직 미확인 |
| 위키→같은 경혈 주소로 복귀 | 단위 검사에서 선택 객체 자체를 보존 | 브라우저 주소·세션 통합 동작은 시나리오만 추가 |
| 새 여성 브라우저 시나리오 | 위키 복귀→같은 경혈 클릭→데스크톱/모바일 화면 저장을 지정 | 이 환경의 개발 서버가 시작되지 않아 시나리오·화면은 실행되지 않음 |

정적 빌드와 TypeScript 검사 통과. 표적 보기 상태 검사19/19, 전체 Node358/359이며 실패1건은 HTTP 경계 검사의 `127.0.0.1 listen EPERM`이다. 표적 Playwright는 `config.webServer`가 종료되어 앱에 진입하지 못했다. agy 읽기 전용 검토도 로컬 `127.0.0.1:0 bind EPERM`으로 시작하지 못했다. 이는 클릭·화면·agy 출시 검증을 통과한 것으로 계산하지 않는다. 원본 메쉬·좌표·박리 투명도 함수와 성별 수록 범위는 바꾸지 않았다. 남녀 전신 해부 정합과 실제 표층→심층 박리는 여전히 미완료다.

후속 실행 환경에서는 서버를 정상 실행한 뒤 이 시나리오를 포함한 관련 브라우저12/12를 통과했다. [같은 경혈 재선택 후 데스크톱](same-point-return-desktop.png)·[모바일](same-point-return-mobile.png)에서 여성 전신50.5% 박리와 경혈·기관 선택 해제를 직접 확인했다. 이전 실패를 당시의 통과로 고쳐 쓰지 않으며, 이 화면도 모든 기관의 정렬·층서를 증명하지 않는다.
