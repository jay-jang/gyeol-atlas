# 남성 췌장 원본 4구조의 두 상세 보기

2026-09-28. 남성 BodyParts3D 4.0의 공식 `FMA7198 pancreas` `partof_element_parts.txt`에는 `FJ1895`·`FJ1896`·`FJ2629`·`FJ2630` 네 OBJ가 수록된다. 기존 남성 별도 상세 자료는 심장·간·폐만 가져왔으므로 췌장은 전신의 두 기존 메쉬만 보였다. 이번에는 고정 Human-Atlas 원본에 이미 있던 네 메쉬를 남성 **별도 상세 출처**로 재포장해 실제 기관·관 구조를 선택할 수 있게 했다. 여성 전신, 여성 CT 상세와 남성 전신 원본의 좌표·형상은 바꾸지 않았다.

| 보기 | 원본 ID | 화면 구성 |
| --- | --- | --- |
| 췌장 · 전체 형상 | `FJ1895` Pancreas, `FJ1896` Pancreatic duct | 주요 기관 목록의 기본 췌장 상세. 각 구조를 개별 선택 |
| 췌장 · 실질·관 가지 | `FJ2629` Parenchyma of pancreas, `FJ2630` Pancreatic duct tree | 기본 보기의 출처 설명·조작 버튼에서 별도 전환, 개별 선택 |

두 췌장 본체 메쉬의 실제 배포 경계상자 모서리 차이는 각 축0.2mm 미만이다. 공간 범위가 거의 겹치는 대체 표현을 한 화면에 중복 렌더링하지 않고 두 묶음을 분리했다. 경계상자 유사성이 표면 동일성이나 임상적 위치 정확도라는 뜻은 아니다. 관 메쉬도 췌장 본체와 같은 출처 좌표를 사용하나, 관의 실제 세부 연결·내강 정확도를 새로 승인하지 않았다. 4.3 관계 목록에는 네 개 중 세 개만 있어 버전을 섞어 누락된 `FJ2630`을 추측해 생성하지 않았다.

## 원본·배포 직접 대조

[공식4.0 다운로드·라이선스 설명](MALE_DETAIL_SOURCE.md)의 ZIP과 관계표를 사용했다. [재현 기록](male-pancreas-source.json)은 ZIP/관계표/가져오기 코드/배포 파일 SHA-256, 네 OBJ의 공식 버전·File ID·원문명·FMA ID, 배포 메쉬 ID와 실제 압축 버퍼를 고정한다. 배포 네 메쉬는 합계 **7,694정점·8,564삼각형**이며 모든 배포 위치 정점이 공식 OBJ의 고정 축·단위 변환 정점에 일치한다. 배포 위치·법선·인덱스 바이트도 같은 고정 Human-Atlas 상류 파일과 일치했다. 이는 수록·재포장 일치 증거이지 삼각형 단순화의 해부학적 정확성이나 HRA/다른 BP3D 전신과의 정합 승인이 아니다.

버전별 다른 폐 묶음은 그대로 유지했다. 4.3 폐563개 실제 버퍼 독립 재읽기에서 위치 잔차0m, 기존 심장·간143개 바이트 보존을 다시 확인했다. 새 췌장4개는 남성 BP4 별도 상세 프레임에서만 로드되며 여성 보기/전통 장부 비교/전신 박리 좌표에 합성하지 않는다. 저장 세션에서 두 대체 묶음의 ID가 섞이면 안전 초기화한다. 모든 진입·전환·복귀는 기존 `view-state.ts`를 거친다.

## 실행·화면과 한계

표적 Node13/13, 전체 Node361/361, TypeScript 및 별도 Node의 Vite 정적 빌드 통과. 췌장·기존 상세·폐 출처·여성 박리·경혈 복귀를 묶은 실제 Playwright **12/12**를 통과했다. 췌장 시험은 기본→대체 보기, 관 가지 개별 선택·새로고침, 기관 묶음 복귀, 50.5% 전신 박리 복귀, 여성 전환 후 BP4 표시0을 확인한다. [데스크톱 전체 형상](male-pancreas-whole-desktop.png)과 [모바일 실질·관 가지](male-pancreas-alternative-mobile.png)를 직접 확인했다. 최초 모바일 캡처에서는 이동 도구가 선택 카드 모서리에 약간 겹쳤다. 기존 폐 세부 보기와 같은 접이식 이동 도구·공통 모바일 배치를 췌장에도 적용해 겹침을 없앴고, 이동 도구와 카드의 실제 경계 간격을 브라우저에서 검사했다. 수정 후 폐·췌장·경혈 복귀를 포함한 **12/12**를 다시 통과하고 모바일 캡처를 재검토했다. 사진만으로 두 메쉬의 내부 관 연결이나 전신 해부 위치는 검증되지 않는다.

후속 프로덕션 스모크는 정적 위키·지연 로딩·남성9 GLB·여성15청크·요청 시 CT1청크·복원·출처와 브라우저 오류0으로 통과했고 모바일 가독성 검사도 보이는 글자 최소12px/대비4.5:1 이상을 확인했다. 이는 공개 HTTPS 배포 검사가 아니다.

agy 읽기 전용 검토는 첫120초 제한에서 미완료였고, 이어받은 응답에서 **최종 포장 스크립트 단독 재실행이 실패하는 문제**를 발견했다. 초기 4메쉬 묶음과 이미 나뉜2+2묶음을 둘 다 받도록 고친 뒤, 최종 스크립트를 다시 실행해 아틀라스·압축 버퍼·그룹·구조 목록 네 파일의 SHA-256이 완전히 동일함을 확인했다. 다른 지적은 두 단계 가져오기를 `import-male-details.mjs`만 단독 실행하면 최종4.3 폐/췌장 보기 분할이 아직 적용되지 않는다는 것이며, 이는 `npm run models:male-details`의 **첫 단계**임을 코드와 아래 명령에 명시했다. agy는 파일을 읽어 정적으로 검토했을 뿐 원본 전수 판독·브라우저·의학 판독을 직접 수행하지 않았다.

수정 후 agy 후속 읽기 전용 답변은 한 묶음/두 묶음 입력 허용과 설명 중복 방지를 확인하고 추가 P1/P2를 보고하지 않았다. 첫 후속 호출은120초 제한으로 답을 받지 못했고, 이어받은 응답에서 완료됐다. 출력 바이트 동일성은 agy의 서술과 별도로 주 에이전트가 실제 네 파일 해시 전후를 대조했다.

```sh
npm run models:male-details
python3 scripts/audit-male-pancreas-source.py
.cache/female-ct-venv/bin/python scripts/verify-lung-packing.py
node --test tests/male-pancreas-detail.test.mjs
```

원본 ZIP과 상류 캐시는 `.cache/`에 둔다. 남녀 전체 기관·뇌·신경의 위치, 여성 상체/위 수록, 실제 피부→심부 박리 정확도는 별도 미완료다.
