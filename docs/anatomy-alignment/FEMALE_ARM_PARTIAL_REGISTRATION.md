# 여성 보완 팔·손뼈의 부분 위치 교정 — 2026-09-20

이 문서는 v1의 역사적 기록입니다. 최신 v2는 [엄지6개 추가 교정](THUMB_REFINEMENT.md)이며, 나머지54개 변환은 유지합니다. 아래915정점은 v1의 결과이고 현재 팔·손의 이탈은372정점입니다.

기존 여성 화면의 남성 유래 보완 골격 중 **팔·손뼈60개에 정적 위치 교정**을 적용합니다. 원본 자료를 여성 고유 골격으로 바꾸거나 전체 정합 완료로 선언하는 변경이 아닙니다. 원본 packed 파일은 보존하고, 복사한 렌더링 정점에만 고정 변환을 한 번 적용합니다. 남성·별도 CT·여성 고유 뇌/기관/혈관/신경/피부에는 이 변환을 적용하지 않습니다.

## 이전 후보의 실패에서 바꾼 점

1. 원본 정점 밀도에 따라 피부 맞춤이 달라지는 문제를 줄이기 위해 삼각형 면적에 비례해 표본화했습니다. 고정 seed, 면적 비율·정점 재구성·서로 다른 세분화의 합성 검사를 추가했습니다. 양쪽 원본의 피부 표본 수는 대략3,500~3,700개입니다. 원본 피부의 안/밖 벽을 새로 분할한 것은 아닙니다.
2. 손목 피부 단면 중심 대신 노뼈–손목뼈 근접 면의 중심을 비교했습니다. 두 기준의 차이는 왼쪽0.726mm·오른쪽1.066mm로 작았으며, 이 변경만으로 이전 교차를 해결하지 못했습니다. 근접 면 중심은 검수된 해부학적 관절 중심이 아닙니다.
3. 이전에는 이미 배포된 위팔뼈 길이를 그대로 고정했습니다. 위팔뼈 전체 축척도 함께 맞추자 원본 대비 왼쪽0.891647·오른쪽0.885411이 됐고, 양쪽 긴뼈6개의 피부 이탈이 없어졌습니다. 위팔뼈 내부 형상을 국소적으로 구부리거나 길이 방향만 늘리지 않았습니다. 허용 축척0.85~1.15와 연결 도달 가능 범위는 실험 경계이지 생리학적 정상 범위가 아닙니다.
4. 손목 교차가 남아 손 전체의 소규모 공통 이동을 검사했습니다. 0.5mm 격자·4mm 반경 안에서 가장 작은 이동 중 첫 무교차 후보를 선택했습니다. 왼손 `[0,-0.5,0.5]`mm, 오른손 `[0,-0.5,0]`mm입니다. 손 내부 상대 위치를 바꾸지 않지만 전완–손목 기준점의 일치는0.707/0.5mm 달라집니다. 이를 정확한 연골 접촉으로 부르지 않습니다.

왼쪽 최종 피부 맞춤은50회 반복 상한에 도달했으므로 완전 수렴으로 보고하지 않습니다. 오른쪽은15회입니다. 후보 채택 판단은 작은 최적화 목적값이 아니라 아래의 실제 정점·전체 골격 쌍 비교와 화면 검사에 근거합니다.

## 런타임과 출처

`data/catalog/female-arm-registration.json`은 지정된60개 borrowed ID, 원본 수록 버전, 행벡터 변환 계수, 검사 수치와 재현 해시를 보관합니다. `src/female-arm-registration.ts`는 여성 전신의 해당 borrowed ID에만 적용하고, 정점·인덱스 수와 중복 적용을 검사합니다. 위치/노멀은 원본 버퍼에서 복사하며, 실제 변환된 경계로 선택·확대·부위 표시를 계산합니다. 박리·선택 상태에서는 다시 변환하지 않습니다.

기존 Human-Atlas/HRA packed 파일15개의 바이트와 해시는 바뀌지 않습니다. 나머지1,160개 모형은 원본 좌표를 유지합니다(여성 고유964개 전부 포함). 교정한 골격도 **BodyParts3D 남성 유래 보완 골격**이며 회청색·출처를 유지합니다. 앱의 ‘보완 골격·근육 정렬 미완료’ 고지를 삭제하지 않았고, 골격 설명에는60개 부분 교정과 남은 손가락 문제를 함께 표시합니다. VIVA+ 자료는 이번 런타임 변경에 사용하지 않았습니다.

### agy 정적 검토의 정정

agy 세션 `e8408ab0-f669-4281-979e-50d147c90f86`은 런타임 정합 함수와 PackedAtlas 연결2개 파일만 검토했습니다. 행렬 전치와 Int16 노멀 읽기를 오류로 지적했으나, 직접 검사에서는 두 지적이 재현되지 않았습니다.

- 저장된 계수는 `q[j] = t[j] + Σ p[k]m[k][j]`라는 행벡터 규약입니다. Three.js의 열벡터 행렬에 전치해서 넣는 것이 의도된 변환입니다. 실제60개 골격의 모든 위치 성분을 이 별도 수식과 대조하는 테스트가 통과합니다.
- 설치된 Three.js의 `normalized=true`인 Int16BufferAttribute의 `getX/getY/getZ`는 정규화된 값을 반환합니다. `[-32767,16384,0]` 입력의 실제 반환값과 변환 후 노멀 길이를 테스트했습니다.

틀린 지적에 맞춰 올바른 행렬을 바꾸지 않았고, 규약 설명과 회귀 테스트를 보강했습니다. agy는 브라우저나 해부학 검수를 수행한 것이 아닙니다.
