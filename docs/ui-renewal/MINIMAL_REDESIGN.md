# 미니멀 아틀라스 재설계 — 2026-09-29

사용자 요청: (1) 박리할 때 각 계통이 해당 단계에서야 나타나는 것처럼 보이니, 모든 것이 존재한 상태에서 하나씩 벗겨지게 할 것, (2) 기존 UX를 버리고 미니멀하면서 상호작용적인 화면으로 다시 설계할 것, (3) 경혈 페이지이므로 여러 경혈을 한꺼번에, 몸과 함께 보이게 할 것.

## 1. 박리: 모든 계통이 존재한 상태에서 바깥부터

이전 순서는 깊이에 따라 계통을 **추가**했습니다(골격 34–44%, 장기 52–62%, 혈관 68–78%, 림프 80–88%, 신경 88–98%에서 나타남). 레이어가 켜질 때만 모델을 불러왔기 때문에 깊은 계통은 실제로 늦게 로드·표시됐습니다.

| 깊이 | 새 표시 | 이전 표시 |
| --- | --- | --- |
| 0% | 7계통 모두 존재(불투명 피부가 덮음) | 피부만 |
| 8–20% | 피부가 사라지며 근육과 그 아래 모든 계통이 드러남 | 피부 → 근육만 |
| 24–64% | 근육이 출처 기반 순서로 한 개씩 사라짐. 골격·장기·혈관·림프·신경은 이미 그 자리에 있음 | 골격·장기가 뒤늦게 나타남 |
| 68–76% | 골격 제거 | 장기가 나타나는 중 |
| 76–84% | 장기 제거 | 혈관이 나타나는 중 |
| 84–90% | 혈관 제거 | 림프가 나타나는 중 |
| 90–95% | 림프 제거 | 신경이 나타나는 중 |
| 95–100% | 신경만 남음 | 신경 |

- 규칙은 `src/dissection.ts` 하나에 있고, 보기 상태는 `src/view-state.ts`의 `dissection` 전이를 거칩니다. 현재 계통은 ‘아직 남아 있는 가장 바깥 계통’(`depthStage`)입니다. 계통 이름을 누르면 그 계통이 가장 바깥이 되는 깊이(0/20/68/76/84/90/95%)로 이동합니다.
- 개별 근육 순서(24–64%, 출처 기반 관계)는 바꾸지 않았습니다. 근육 박리 감사 결과는 파일 해시만 달라졌고 관계 위반0입니다.
- 새 단위 검사: 0%에서 모든 계통 불투명도1, 어떤 계통도 다시 나타나지 않음, 안쪽 계통은 바깥 계통이 모두 사라진 뒤에만 감소(`tests/dissection.test.mjs`). 저장된 진행형 보기는 복원 시 새 순서로 다시 계산해 구버전 레이어 조합이 계통을 숨기지 않게 했습니다.
- 대가: 모든 계통이 처음부터 존재하려면 아틀라스 첫 진입 때 남성 모델 9개(약 64MB)를 모두 받습니다. 피부(1MB)가 먼저 그려지고 나머지는 배경에서 함께 로드되며, 상태 줄이 ‘내부 계통 불러오는 중 n/7’을 표시합니다. 위키는 여전히 3D·모델을 요청하지 않습니다(Q9). 이 변경으로 Q15의 ‘초기 체표만 지연 로딩’ 기준을 개정했습니다.

## 2. 미니멀·상호작용 화면

이전: 왼쪽 탐색 사이드바(검색·성별·부위·깊이 카드·계통 카드·주요 기관), 떠 있는 도구 막대와 도킹 패널 4개, 경혈 요약 칩, 하단 안내 그리드, 이동 패드.

새 구성(`src/AtlasPage.tsx`, `src/atlas.css`):

| 영역 | 역할 |
| --- | --- |
| 전체 화면 인체 | 헤더 아래 전부가 3D 장면입니다. |
| 위: 통합 검색 | 경혈 코드·이름, 구조 한국어·영어·FMA, 기관 상세를 한 입력에서 찾습니다(`/`). 빈 입력은 기관 상세 바로가기를 보여 줍니다. 고르면 결과가 닫히고 입력은 남습니다. |
| 위 오른쪽 | 남성/여성, 부위, 표시 설정(레이어·표식·선택 대상·앞쪽 숨기기), 도움말 |
| 왼쪽: 깊이 막대 | 세로로 끌어 박리합니다. 계통 이름을 누르면 그 깊이로, 눈 버튼은 그 계통만 봅니다. 벗겨진 계통은 흐리게 표시됩니다. 휠·Alt+휠·Alt+↑/↓를 유지합니다. |
| 아래: 경혈 막대 | 경혈 표식 켜기/끄기와 개수, 15개 경맥 칩, 이름 표시, 목록·필터 |
| 오른쪽: 선택 정보 | 선택 경혈 칩(누르면 상세), 경혈 상세 카드, 구조·비교·기관 상세 카드 |
| 아래 오른쪽 | 이동(WASD 대체 버튼), 정면·후면·측면, 확대·축소·맞춤·초기화 |
| 아래 왼쪽 | 로드 상태, 선택 대상, 선택 시 범례, 출처 줄(여성 보완 한계 포함) |

- 휴대폰: 위 검색·깊이 막대, 아래 경혈 막대, 오른쪽 세로 도구. 목록·설정·도움말과 선택 정보는 장면의 45% 이하 하단 시트입니다. 짧은 가로 화면은 깊이 막대에 점과 현재 계통 이름만 보입니다.
- 아이콘 버튼의 설명은 마우스 호버와 키보드 초점에서 모두 보입니다(`data-tip`). 모든 동작은 클릭·터치로 실행되고 Escape로 패널을 닫으면 연 버튼으로 초점이 돌아갑니다.
- 유지한 것: 보기 상태 규칙과 저장·복원, 위키 왕복, 카메라·표식 선호 보존, 단일 구조와 전통 장부 비교 묶음 구분, 기관·폐·췌장·콩팥·여성 CT 상세와 모든 출처·한계 문구, 여성 보완 골격·근육의 한계 표시. 표시 순서만 바뀐 것이며 해부 좌표·모델·수록 범위는 바꾸지 않았습니다.
- 선택 카드 위치가 데스크톱은 오른쪽, 휴대폰은 아래, 짧은 가로는 왼쪽이므로 카메라 맞춤은 측정한 카드 위치의 반대쪽 빈 영역에 모델을 맞춥니다.

## 3. 경혈: 여러 개를 몸과 함께

- 기본값이 ‘선택 경혈만’에서 ‘필터 결과 전체’로 바뀌어 남성 기준 409개 명칭·834개 표식이 처음부터 몸 위에 보입니다. 저장된 세션의 표식 선호는 그대로 유지합니다(Q2).
- 경맥 칩 하나로 그 경맥만(예: 위경 45혈) 남기고, 목록 패널의 분류(원혈·모혈·오수혈·낙혈)·신체 부위·수록 범위·저장 필터가 표식에 바로 반영됩니다. 선택 경혈은 필터 밖이어도 표시합니다.
- 표식의 바깥 방향(표시 위치와 체표 점의 차이)으로 카메라를 향하는 면만 보이게 해, 정면에서 등 쪽 경혈이 몸을 뚫고 보이지 않습니다. 후면으로 돌리면 방광경 등 뒷면 경혈이 나타납니다. 선택 경혈은 모든 방향에서 보입니다.
- 이름표는 호버·선택 시, 또는 ‘표식 이름 표시’로 필터 결과 전체에 붙습니다. 이름표는 화면 픽셀로 표식 옆에 두고 캔버스 밖으로 잘리지 않습니다.
- 표식은 체표 기준 위치이므로 박리 중에도 남아, 근육·골격·장기와 경혈을 함께 봅니다. 이는 위치 비교용이며 경혈과 내부 구조의 연결이나 압력 경로를 뜻하지 않습니다.
- 여성 표면 좌표는 검수 전이므로 표식을 숨기고 그 이유와 ‘남성 모델에서 경혈 보기’를 경혈 막대에 표시합니다. 장부 비교를 위한 경혈 목록 선택은 유지합니다.

## 4. 모든 계통을 그리는 비용과 처리

모든 계통이 0%부터 존재하므로 남성 전신은 한 프레임에 약 2,100개 메쉬를 그립니다. 같은 Chromium에서 직접 잰 값입니다.

| 조건 | 첫 준비 | 프레임 | 그리기 호출 |
| --- | --- | --- | --- |
| 소프트웨어 WebGL(SwiftShader), 0% | 7–60초(부하에 따라) | 약 2.6–3.6초 | 2,092 |
| 로컬 GPU(Apple M5, ANGLE Metal), 0% | 약 2–3초 | 15–17ms | 2,092 |

- 경혈 834개를 개별 메쉬 대신 하나의 인스턴스 메쉬로 그려 그리기 호출을 834개 줄였습니다. 크기는 화면 기준으로 유지하고, 뒷면·필터 밖 표식은 크기0으로 숨기며, 선택·호버·클릭은 인스턴스 번호로 처리합니다.
- 검색 입력·패널 열기처럼 3D와 무관한 조작이 장면 전체를 다시 그리던 원인을 없앴습니다(매 렌더 새로 만들던 빈 배열·기본 경혈 객체·마커 목록·캔버스 설정 객체). 40% 깊이에서 검색 입력·패널 조작 중 3D 프레임0, 0.86초(이전 30초 초과).
- 검토 후 **채택하지 않은 방법**: 피부가 불투명할 때 안쪽 계통을 그리지 않는 최적화. 여성 기증자 근육처럼 피부 밖으로 벗어난 알려진 정렬 문제가 있어, ‘피부가 모두 덮는다’는 가정이 틀리고 실제로 보이는 결함을 숨기게 됩니다. 존재하는 모든 계통을 그대로 그립니다.
- 브라우저 검사는 기본 SwiftShader를 유지하고, `PLAYWRIGHT_GPU=1`이면 로컬 GPU(macOS Metal)로 실행합니다. 이번 재설계의 전체 브라우저 검사는 GPU로 실행했으며 기록에 렌더러를 밝힙니다.

- 이전 화면을 전제로 한 1회성 공개 확인 스크립트(`scripts/check-*-pages.mjs`, `scripts/smoke-female-*.mjs` 등)는 선택자만 기계적으로 옮겼고 다시 실행하지 않았습니다. 표준 게이트(`npm test`, `npm run test:e2e`, `test:visual`, `test:production`, `test:geometry`, `audit:overlays`, 가독성)는 다시 실행했습니다.

## 한계

- 첫 아틀라스 진입의 모델 전송량과 디코딩이 커졌습니다. 소프트웨어 WebGL 검사에서는 페이지당 로드·프레임이 길어 브라우저 검사 기본 제한 시간을 150초로 늘렸습니다.
- 헤드리스 Chromium·ANGLE Metal 검사 환경에서 브라우저 전체가 수십 초–수 분 멈추는 간헐 현상이 있습니다. 멈춘 동안 페이지는 `1+1` 평가·타이머·애니메이션 프레임에 응답하지 않고 JS 호출 스택이 없으며, 새 페이지 이동도 끝나지 않습니다. 앱 오류나 WebGL 컨텍스트 손실 기록은 없었습니다. 같은 재현 절차에서 재설계 전 커밋(801c730)도 40회 중 4회 멈춰(전체 멈춤 1회) 이번 변경이 새로 만든 문제는 아니라고 판단했지만, 원인은 확인하지 못했고 실제 브라우저에서 발생하는지도 검증하지 않았습니다.
- 소프트웨어 WebGL에서 데스크톱→휴대폰 크기로 줄인 뒤 목록 패널을 열면 패널 위쪽 3D 화면이 비어 보이는 현상이 6번 중 5번 재현됐습니다(패널을 닫으면 복구, GPU·휴대폰 크기로 새로 연 페이지는 정상). 강제 재렌더로 복구되지 않았고 원인은 확인하지 못했습니다([재검증 기록](../anatomy-alignment/VERIFICATION.md)).
- 깊이 0–68%에서는 약 2,000개 메쉬를 그립니다. 로컬 GPU에서는 15ms대였지만 저사양 휴대폰·통합 그래픽의 프레임 속도와 모바일 데이터 사용량(첫 진입 약 64MB)은 측정하지 않았습니다.
- 표식 앞뒤 판단은 표시용 오프셋 방향을 법선으로 쓴 근사입니다. 옆구리처럼 경계에 있는 점은 각도에 따라 보였다 사라질 수 있습니다.
- 실제 휴대폰·태블릿과 사용자 과업 성공률은 검증하지 않았습니다. 상용 서비스를 새로 비교해 채택한 설계가 아닙니다.
