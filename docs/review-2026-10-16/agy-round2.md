## 2. 자기 1차 안(`A-1`–`A-12`)에서 철회·수정하는 항목

1. **`A-1` (첫 방문 한 줄 안내 배너) → 철회 (`L-10.1` 수용)**
   - **이유**: 닫기 버튼이 있는 첫 방문 배너라도 코치마크처럼 보일 수 있고, 78장 촬영 스크립트와 레이아웃 오버레이 감사(`audit-scene-overlays.mjs`)에서 추가 오버레이 박스로 간섭합니다. 대신 상시 도구에 명확한 한글 텍스트 라벨(`경혈 찾기`, `표시 설정`, `박리 깊이`)을 붙이고 빈 경혈 칩 안내(`경혈 선택 · 표식을 누르거나 목록에서`)와 입력 방식별 도움말 표로 U1을 해결합니다.
2. **`A-7` (세로 깊이 막대 균등 간격 7행 배치) → `L-04` (비례 위치 + 최소 간격 `minGap`, 최대 높이 `≤520px`)로 수정**
   - **이유**: 정지점을 완전 균등 간격(`100/7%`)으로 바꾸면 연속 슬라이더 썸(thumb)의 실제 위치(`0%`, `5%`, `12%`...)와 옆에 있는 계통 버튼의 높이가 어긋납니다. 비례 위치를 기본으로 하되 최소 간격(`32px`/`36px`)만 밀어내어 겹침을 0으로 만드는 `L-04`가 슬라이더와의 시각적 대응이 훨씬 정확합니다.
3. **`A-4` (모바일 상단 2행에 박리 슬라이더 + 7계통 칩 배치) → `L-02` + `L-03` 절충(상단 1줄 축소 + 하단 엄지 영역 깊이 바 + 팝오버)으로 수정**
   - **이유**: 모바일 세로에서 박리 슬라이더를 상단 2행에 두면 한 손 엄지 조작(U9)이 어렵고 상단 크롬이 두꺼워집니다. 상단은 `[검색][남\|여][방패][설정]` 1줄(44px)로 줄이고, 박리 조절은 하단 엄지 영역의 깊이 바 + `[깊이·계통 ▾]` 팝오버로 내립니다.
4. **`A-6` (모바일 가로 844×390에서 시트를 오른쪽 드로어로 전환해 높이 100% 허용) → 철회하고 `L-06` (`max-height: 45%` 준수) 수용**
   - **이유**: 브리프의 바꿀 수 없는 조건에 *"모바일 바텀 시트(또는 드로어)가 열려도 3D 장면 높이는 화면의 45% 이하만 가립니다"*가 명시되어 있고, 현재 [`atlas.css:511`](file:///Users/nuinuri/workspace/anatomy/src/atlas.css#L511)의 `max-height: calc(100% - 70px)`가 이를 위반하고 있습니다. 임의로 폭 기준으로 재해석하지 않고 가로 화면에서도 패널 `max-height: 45%`를 엄격히 지킵니다.
5. **`A-10` (위키 상단 검색·질문 단일 입력창 통합) → `C-10` / `L-21` (목차 내 문서 제목 검색 + 본문 내 컴팩트 ‘질문으로 문서 찾기’ 분리 유지)로 수정**
   - **이유**: 위키 문서 제목 즉시 필터링(`q` state)과 키워드 기반 본문 검색/요약(`askWiki` API/정적 매칭)은 동작 시점(즉시 필터 vs submit)이 다르고, 기존 테스트 7곳이 `getByLabel('위키 질문')`과 `'질문 보내기'`를 별도 폼으로 검증합니다. 장식(Sparkles, 슬로건)만 제거하고 두 입력의 역할은 명확히 분리하는 편이 직관적이고 안전합니다.
