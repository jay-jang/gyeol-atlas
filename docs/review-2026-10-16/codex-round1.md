# 1. 요약

- **C안은 ‘인체 위에서 찾고, 관찰하고, 읽는 도구’로 화면을 재구성합니다.**
- 데스크톱은 간결한 도구 막대와 선택 패널, 모바일은 엄지 영역의 탐색 도구와 하나의 하단 시트를 사용합니다.
- 검색 대상 구분, 위치 설명 우선 배치, 접히는 필터로 핵심 과업의 우회와 스크롤을 줄입니다.
- 비교 종료 후 보기 복원과 작은 화면의 패널 충돌을 시각 개편보다 먼저 해결합니다.
- 모델·출처·근사 고지와 R1–R8 보정은 유지하며, 위키의 마케팅·대화형 연출은 문서 탐색 중심으로 정리합니다.

# 3. 설계 원칙

1. **과업의 순서를 화면의 순서로 만듭니다.** 검색 → 선택 → 위치 확인 → 상세·비교·문서로 이어지게 합니다.
2. **장면을 항상 유지합니다.** 패널은 캔버스 위에 뜨며, 모바일에서는 제목·고지·조작부를 포함해 높이 45%를 넘지 않습니다.
3. **대상과 동작의 범위를 명시합니다.** 경혈, 개별 구조, 기관 상세, 전통 장부 비교를 이름과 버튼 문구로 구별합니다.
4. **사용자의 관찰 의도를 보존합니다.** 패널 열기·닫기로 카메라를 움직이지 않고, 보기 변경은 공통 상태 전이를 따릅니다.
5. **장식을 줄이고 읽을 정보를 남깁니다.** 하나의 UI 강조색, 명확한 글자 위계, 실제 의미가 있는 색·수록 범위·출처·검수 상태를 사용합니다.

# 4. 화면 크기별 배치 명세

공통으로 **캔버스는 헤더 바로 아래부터 화면 끝까지 유지**합니다. 아래 도식의 도구 영역은 캔버스 위의 부유 요소이며 고정 사이드바로 장면을 밀어내는 구조가 아닙니다.

배치 적용 순서는 **낮은 높이 대응 → 폭 대응**입니다. 1280×720도 낮은 높이 배치를 사용하며, 가상 키보드가 열리면 보이는 화면 높이에 맞춰 시트 상한을 다시 계산합니다.

```text

├───────────────────────────────────────────┤
│ [경혈·구조 검색 /]     [남/여][부위][가리기]│

- 헤더 52px, 화면 안쪽 여백 12–16px.
- 검색 너비 320–360px, 깊이 도구 96–112px, 선택 패널 336–360px.
- 검색 결과·목록·표시 설정·도움말은 **같은 작업 패널 자리**를 사용합니다. 검색 입력 아래에 별도의 큰 결과 상자를 겹치지 않습니다.
- 선택이 없으면 패널을 비워 모델 관찰 공간으로 둡니다.
- 패널 안에서는 제목·닫기·핵심 조작을 고정하고 본문만 스크롤합니다.

│                          │짧은 내용 / 스크롤 ││
│                          │대상별 조작        ││
│                          └───────────────────┘│
│ [경맥∨][현재 경혈·이전/다음]       [시점][더보기]│
└────────────────────────────────────────────────┘
```

- 헤더 44px. 긴 깊이 막대·경맥 칩 열·카메라 열을 상시 표시하지 않습니다.
- 패널은 한쪽에 너비 280–320px로 배치하되 **높이도 장면의 45% 이하**로 제한합니다. 옆에 놓는다는 이유로 높이 제한을 면제하지 않습니다.
- 844×390에서는 장면 높이 346px 기준 약 155px가 상한입니다. 제목·필수 고지·핵심 조작을 우선하고 나머지는 본문 스크롤과 위키로 제공합니다.
- 검색·설정·시점은 동일한 패널을 교체해서 사용합니다.
- 공간 부족을 글자 축소로 해결하지 않습니다.

**공통 충돌 규칙:** 검색·상세·설정 등 큰 작업 패널은 하나만 엽니다. 대체된 도구는 실제로 숨겨 중첩을 제거하고, 단순히 뒤에 깔지 않습니다. 패널 열기 때문에 카메라를 자동으로 확대·이동하지 않습니다. 가려진 대상을 확인하는 ‘확대’는 사용자가 누르는 명시적 동작으로 유지합니다.

### 디자인 토큰

모든 공통 토큰을 `src/design-system.css`에서 정의하고 아틀라스·문서 화면은 이를 참조합니다. 현재 `atlas.css`의 별도 색·간격 정의를 점진적으로 통합합니다.

| 항목 | 제안 |
|---|---|
| **색** | 장면은 어두운 배경 유지. 도구는 불투명한 중립 표면, 문서는 흰색 계열. UI 강조는 녹청 계열 하나를 사용하되 밝은 표면과 어두운 표면에 각각 대비가 확보되는 명도 사용. 예: 밝은 표면 `#245F50`, 어두운 표면 `#8ACFC1`을 검증 후보로 삼음. |
| **의미 색** | 해부 계통·경맥·선택·비교·근사 상태 색은 유지. ‘강조색 하나’를 이유로 의미 색을 단색화하지 않음. |
| **글자** | 도구 기본 14px, 보조 12px 이상, 위키 본문 16px·행간 약 1.75, 패널 제목 18px, 문서 제목 26–30px. |
| **간격** | 4 / 8 / 12 / 16 / 24 / 32px. 작은 화면에서도 행 사이의 조작 여유를 보존. |
| **모서리** | 입력·버튼 4px, 부유 패널 8px. 원형은 표식·색 견본처럼 의미가 있을 때 사용. |
| **그림자** | 부유 패널의 높이 구분에만 약하게 사용. 일반 목록·본문에는 그림자를 적용하지 않음. |
| **조작 영역** | 터치 대상은 44×44px를 기본 목표로 함. 의미 있는 글자는 최소 12px, 텍스트 대비는 실제 렌더 표면에서 4.5:1 이상 검증. |

‘AI스러운 UI’ 배제 정의에는 대체로 동의합니다. 다만 **의미를 전달하는 색과 실제 생성 이력을 밝히는 고지는 장식과 구별**해야 합니다. 경맥 색이나 ‘AI 작성·전문가 미검수’를 없애는 방향은 제안하지 않습니다.

# 8. 유지할 것 / 하지 않을 것

**유지할 것**

- 인체가 주 작업 공간인 구성과 어두운 관찰 배경.
- 409개 명칭·834개 표식의 구분, 남성 기본 전체 표식, 여성 근사 표식의 명시적 선택.
- 연속 박리의 0.5% 단위와 기존 제거 순서.
- 모델 직접 선택과 검색 선택의 차이, 개별 구조와 장부 비교 전체 묶음의 구별.
- 카메라·표식 선호·위키 왕복·새로고침 복원.
- R1–R8의 초점 복귀·탭 이동·CT 버튼 복원·정확한 비교 이름·툴팁.
- 영어 원문명·FMA·TA2·출처·검수 상태·좌표계 제한.
- 키보드·터치 이동, 동작 줄이기 설정, 성기 가리기 선호.

**하지 않을 것**

- 장면을 대체하는 모바일 전체 화면 탐색 탭.
- 도구를 숨긴다는 이유로 클릭·터치·키보드 경로를 제거하는 변경.
- 기본 표식을 자동으로 줄이거나 계통을 실제 조직 깊이처럼 설명하는 변경.
- 비교를 단일 메쉬 선택으로 축소하거나 장부 대응을 해부학적 연결로 표현하는 변경.
- UI 작업에 해부 형상·정합·수록 범위 변경을 섞는 작업.
- 장식용 그라데이션·글로우·블러·반복 카드·영문 슬로건·질문형 히어로.
- 모든 설명을 도움말로 보내 필수 한계까지 감추는 변경.
- 새로운 계정·클라우드 저장·공유 서버 도입.

상태 복원은 다음 정책을 제안합니다.

- 비교가 자동으로 적용한 피부 반투명·레이어·선택 대상은 **임시 효과**로 관리합니다.
- 비교 중 사용자가 직접 바꾼 선호와 자동 효과를 구별합니다. 종료 시 직접 편집한 값은 유지하고 나머지는 진입 전 값으로 복원합니다.
- 단독 보기 해제는 비교 문맥으로 돌아가며, 비교 종료와 구별합니다.
- 비교를 끝내는 구조 선택·계통 전환도 같은 공통 종료 규칙을 거칩니다.
- 종료 시 현재 카메라는 유지합니다. 다른 좌표계의 기관 상세 왕복은 기존 복원 규칙을 따릅니다.
- 복원 정보가 없는 구버전 저장값에서 과거 선호를 추정해 만들지 않습니다.

**필수 검증 범위**

- `npm test`, 적용 브라우저 검사, `npm run build`, `npm run test:production`.
- `npm run test:visual`, `npm run audit:overlays`, `node scripts/check-readability.mjs`.
- 겹침 검사에 `.ax-results`, `.ax-side-panel`과 실제 열린 상태를 추가합니다.
- 여섯 기준 크기의 13상태를 다시 비교하고, 여성 근사 표식 켜기·CT 상세·기관 상세 복귀·필터 결과 없음도 추가합니다.
- 검색 입력·시트·카메라·상태 줄을 포함해 화면을 직접 검사합니다. DOM 경계 통과만으로 완료 처리하지 않습니다.
- 캔버스 초점에서만 키보드 이동, 키 해제·초점 이탈·검색 입력·Alt/Option 박리 경로를 확인합니다.
- 실제 기기와 스크린리더 검증은 자동 검사와 별도로 기록합니다. 미실행 항목은 완료로 표시하지 않습니다.

# 10. 예상 반론과 트레이드오프

| 예상 반론 | 판단과 대응 |
|---|---|
