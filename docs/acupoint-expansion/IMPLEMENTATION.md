# 409개 경혈 구현 기록

2026-09-16. 정규 14경맥 361개 + 경외기혈 48개. 이름 수와 양측·다중 위치 표식 834개를 구분합니다.

## 데이터와 근거

- `data/acupoint-catalogue.json`: KMCRIC 15개 목록의 코드·한국어명·한자명. EX-HN15, EX-CA1, EX-B9, EX-UE11, EX-LE12를 합쳐 48개. 타 자료의 다른 EX 번호를 이름 대조 없이 합치지 않았습니다.
- `data/acupoint-content.json`: 항목별 위치의 짧은 발췌·요약, 전통적 활용의 한국어 요약, 원문 URL·라이선스. TCM Wiki 유래 내용은 CC BY-SA 4.0이며 새 번역·요약임을 밝힙니다. EX-UE6은 eLotus 별도 요약입니다. ST17은 기준점으로만 설명하며 효능을 만들지 않았습니다.
- `data/acupoint-theory.json`: 경맥 음양·오행과 오수혈 60개의 개별 오행을 분리했습니다. LU9는 폐경의 금과 수(輸)혈의 토를 함께 표시합니다. 임맥·독맥·경외기혈에는 임의의 오행을 붙이지 않습니다.
- `data/acupoint-seeds.json`: 단일 BodyParts3D 모델 위에 편집한 학습용 좌표. 전문가 취혈 검수가 아닙니다. 기존 36개 원본 저술은 `data/acupoint-authoring/`에 보존합니다.
- `scripts/assemble-acupoints.py` → points/point-concepts → `scripts/build-anchors.mjs` → 실제 피부 표면 투영 → `scripts/build-wiki.mjs` → 위키 419편. 일반 빌드는 체크인된 데이터만 사용하며 조사용 캐시 다운로드가 필요하지 않습니다.

## 표현과 상호작용

11개 세부 부위, 기존 4개 대분류, 경맥·원혈·모혈·오수혈·낙혈·검색·저장 필터를 조합합니다. ‘필터 결과를 모델에서 보기’는 실제 표식 집합을 표시하고 그 범위에 시점을 맞춥니다. 전이는 공통 view-state를 사용하며 위키 왕복에서 필터·카메라를 복원합니다. 모바일 패널은 모델 위에서 높이를 제한합니다.

협척은 34곳, 십선·기단은 각각 10곳, 사신총은 4곳입니다. 금진/옥액은 좌/우를 구별합니다. 구강·비강 내부 6개 항목은 내부 메쉬에 정확히 정합한 좌표가 없으므로 외부 부위 참조라고 명시합니다. 레이블은 다중 위치마다 반복하지 않습니다.

## 편집·정확도 한계

- 834개 앵커가 피부 메쉬 위에 있다는 검사는 취혈 위치의 임상 정확도를 검증하지 않습니다. 원점에서 표면까지 최대 이동은 70.2mm입니다. 비례촌·자세·개인차를 임상 수준으로 정합하지 않았습니다.
- 신규 항목의 개별 해부 구조 FMA 연결은 미검수 상태로 비워두었습니다. 기존 검토된 36개 연결만 유지합니다. 경혈 선택을 장기 압력 경로로 설명하지 않습니다.
- KMCRIC의 사봉(EX-UE10) 설명은 끝마디 사이관절을 먼저 제시하고 몸쪽 관절의 이설도 적습니다. 소골공(EX-UE6)의 관절 위치 역시 eLotus 설명과 다릅니다. 앱은 KMCRIC 위치 설명을 보존하며 이 차이를 임상적으로 판정하지 않았습니다.
- CV17은 KMCRIC 표기 ‘단중’을 사용합니다. 기존 ‘전중’ 표기와 다른 점을 기록합니다. 한국어 요약은 공식 WHO 번역이 아닙니다.
- WHO 서지 자료와 KMCRIC를 구분합니다. WHO PDF에 대한 직접 접근 제한이 있어 모든 페이지를 직접 대조했다고 주장하지 않습니다. 전통 용도의 자료가 현대 임상 효능을 입증하지 않습니다.
- TARA의 비영리·변경금지 온톨로지는 배포 데이터로 채택하지 않았습니다. eLotus Five Shu 표의 SI/ST 링크 오기는 다른 표와 대조해 그대로 가져오지 않았습니다.

## 정적 배포

GitHub Pages는 `/gyeol-atlas/`를 기준으로 모델·Markdown·manifest 경로를 만듭니다. 위키 최초 진입은 WebGL/GLB 없이 동작합니다. 서버와 브라우저가 `shared/knowledge.mjs`의 동일 검색·근거 제한 로직을 사용합니다. Pages에는 LLM 서버를 연결하지 않으며 저장된 문서를 검색합니다. Cloudflare의 Node 서버 모드는 기존 선택적 LLM 구성을 유지합니다.
